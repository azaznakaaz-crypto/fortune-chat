### 0-2. Square公式情報の確認方法について

- この作業環境では、Square公式サイト（squareup.com）を直接開くことがネットワーク設定で制限されていました。
- そのため、**Square公式ページを対象にした検索結果の要約**から確認しています。ページ本文を直接読んだわけではありません。
- 下の表では、確認の確かさを次の記号で分けています。**公開前・契約前に、必ず公式ページで最新の内容をご確認ください。**

  - △：Square公式コミュニティの告知、公式ブログ記事、または米国版ヘルプでの確認（日本での条件は要確認）
  - ×：確認できていない（推測で書いていません）
- 作業環境の設定で「squareup.com」への接続を許可すると、公式ページを直接読み込んで再確認できます（画面上部の環境メニュー →「編集」→ ネットワークアクセス）。

## 1. 全体の方針（結論）

**お金・在庫・予約・お客様情報の「正しい記録」はすべてSquareに置き、Arcisのサイトは「案内と入口」に徹します。**

| 役割 | 使うもの | 理由 |
|---|---|---|
| 教室の案内・写真・文章 | Arcisのサイト（リーフレットの世界観で制作） | デザインを自由に作れる |
| 商品の販売・在庫・送料・発送 | Square オンラインビジネス（ネットショップ機能） | 在庫・送料・配送先・発送状況が標準で扱える |
| グループレッスンの予約・定員・受講料 | Square 予約「クラス」機能（有料プラン） | 定員管理と事前決済が標準で扱える |
| 個別レッスンの予約 | Square 予約「サービス（1対1の予約）」 | 同じ管理画面で扱える |
| カード決済 | Squareの決済画面 | カード情報をArcis側で扱わない |

この形にすると、**サイト側ではお客様の個人情報もカード情報も保存しない**ため、守るべきものが少なく、運営も簡単になります。

## 3. 利用の流れ

### 3-1. 商品を購入する（お客様）

1. Arcisのサイトで商品を見る
2. 「購入画面へ」を押す → 「Squareのオンラインショップに移動します」と案内を表示
3. Squareの画面で数量を選び、カートへ
4. お届け先・連絡先を入力（送料が自動で計算される）
5. Squareの決済画面でお支払い
6. **支払いが成功した時点で注文成立**。Squareから確認メールが届く
7. 発送したら、運営者がSquareで「発送済み」にする → お客様に通知

### 3-2. グループレッスンを予約する（お客様）

1. サイトの「開催予定」で日程を選ぶ（残席の目安を表示）
2. 「予約する」を押す → 「Squareの予約画面に移動します。支払い完了で予約成立です」と案内
3. Squareの予約画面で回を選択（満席の回は選べない）
4. お名前・連絡先を入力し、受講料を事前にお支払い
5. **支払いが成功した時点で予約成立**。確認メールが届く
6. 前日などにSquareからお知らせ（設定による）
7. 当日参加（オンラインの場合は参加URLの案内。方法は要検討）

### 3-3. 個別レッスンを予約する（お客様）

1. 個別レッスンのページで「日時を選んで予約」
2. Square予約の画面で空いている日時を選ぶ
3. 事前決済を必須に設定した場合は、支払い完了で予約成立
4. 「まず相談したい」場合はLINEなどで受け付け、運営者がSquareで予約を作成

### 3-4. 運営者の日々の作業

| 作業 | 場所 |
|---|---|
| 新しい開催日を追加・定員を変える | Square予約（パソコン・スマホのアプリ） |
| 参加者一覧を見る | Square予約（各回の予約者） |
| 商品を追加・価格を変える | Squareの商品ライブラリ |
| 入荷した数を足す | Squareの在庫管理 |
| 注文を確認・発送済みにする | Squareの注文管理 |
| 返金する | Squareの取引履歴から |
| 写真・文章・お知らせを変える | サイトの更新画面 |

## 4. Squareで管理するもの／サイトで管理するもの

**原則：数字（価格・在庫・定員・残席・支払い）とお客様情報はSquareを「正しい記録」にし、サイト側で二重に入力しない。**

| 項目 | 正しい記録の場所 | サイト側の扱い |
|---|---|---|
| 商品名・価格・写真（販売用） | Square | 最小構成：Squareのショップへリンク／将来：Squareから自動で読み込んで表示 |
| 在庫数・入荷・販売・返品 | Square | 表示のみ（最終判定はSquareの購入画面） |
| 送料・配送先・発送状況 | Square | 持たない |
| 購入者と注文 | Square（顧客リスト・注文） | 持たない |
| レッスン日程・定員・残席 | Square予約 | 最小構成：Square予約へリンク／将来：自動表示を検証 |
| 申込者と予約・支払い | Square（予約・顧客・取引） | 持たない |
| 教室紹介・レッスン説明・写真・お知らせ・よくある質問 | サイト | サイトの更新画面で編集 |
| 規約・特定商取引法表記 | サイト | 内容はSquareの設定（キャンセル条件など）と一致させる |

### 購入者・申込者と支払いの照合

- Squareでは、支払い・注文・予約が**同じお客様（顧客リスト）に結び付いて**記録されます。サイト側に一覧を作らないので、照合作業はSquareの画面だけで完結します。
- 現金や振込など、Square以外で受け取る支払いは**作らない**ことを推奨します（照合が手作業になるため）。

## 5. 状態の区別と、在庫・残席を戻す条件

### 5-1. 商品

| 状態 | どう判断するか | 在庫 |
|---|---|---|
| 未払い | 支払いが済むまで注文は成立しない（カートにあるだけ） | 減らない |
| 決済失敗 | Squareの画面で再入力を求める。注文は成立しない | 減らない |
| 支払済み | Squareの注文に「支払い完了」 | 販売で減る |
| 発送済み | 運営者がSquareで発送済みにする | 変化なし |
| キャンセル（発送前） | 運営者が返金 → 注文を取り消し | **戻す** |
| 返品（発送後） | 商品が届き、状態を確認してから返金 | 再販売できる場合のみ**戻す**／傷んでいれば戻さない |
| 返金済み | Squareの取引に返金記録 | 上の条件による |

- 在庫0の商品は、Squareのショップ上で「売り切れ」になり購入できない設定にします（標準機能。◯〜△、公開前テストで確認）。
- 返金時に「在庫に戻すかどうか」を選べるか、どの画面で行うかは**公開前に実際の画面で確認**します（×）。

### 5-2. レッスン

| 状態 | どう判断するか | 残席 |
|---|---|---|
| 未払い | オンライン予約では事前決済が必須のため、**未払いの予約は作られない** | 減らない |
| 決済失敗 | 予約は成立しない | 減らない |
| 予約成立＝支払済み | 支払い完了と同時に予約成立 | 1席減る |
| お客様によるキャンセル | 期限内なら返金（Squareの告知では、クラスのキャンセル時は自動で払い戻し △） | **戻す** |
| 期限後のキャンセル・無断欠席 | キャンセル規定どおり（返金なし等。規定は要決定） | 戻す（空いた席を他の人が予約できる） |
| 教室都合の中止 | 運営者が回を取り消し、全員に返金 | 回ごと削除 |
| 返金済み | Squareの取引に返金記録 | ― |

### 5-3. 売り越し・二重予約・満席時の申し込みを防ぐ

- **販売と予約の最終判定は、すべてSquareの画面で行います。** サイトに表示している在庫や残席は目安で、Squareの画面で「在庫切れ」「満席」なら申し込めません。
- 同時に申し込みがあった場合の処理はSquareの内部で行われます。**Squareが内部でどう処理しているかは公開資料で確認できていない（×）ため、公開前に「残り1席に2台のスマホから同時に申し込む」「残り1個の商品を同時に購入する」テストを必ず行います。**
- サイト側で独自に在庫・残席を数えることはしません（Squareと数字がずれる原因になるため）。

## 7. 最小構成と、将来追加できる機能

### 7-1. 最小構成（おすすめの始め方）

- Arcisのサイト（案内ページ）＋ Square オンラインビジネス（商品）＋ Square予約（レッスン）
- サイトから各Square画面へリンクするだけ。**サイト側にサーバーの仕組み・お客様情報・秘密の鍵を持たない**
- トップページの「開催予定」「商品紹介」は、最初は「代表的な回・おすすめ商品」を運営者が載せ、**残席・在庫・最新価格は「予約画面／購入画面で最新を表示」**と案内する（二重管理の範囲を小さくする）

### 7-2. 次の段階（二重入力をなくす）

- サイトのサーバー側で、Squareから**商品・価格・在庫を読み取って自動表示**（書き込み・決済はしない）
- Square予約のクラス日程・残席を自動表示できるかを、Squareのテスト環境で検証してから判断
- 在庫の少ない商品を運営者にお知らせ、など

### 7-3. 追加候補（必要性と日本での対応状況を確認してから）

| 機能 | 日本での対応状況 | 注意点 |
|---|---|---|
| 月会員（月謝の自動課金） | Squareの「サブスクリプション」「カード情報の保存による自動引き落とし」が日本の公式情報で案内されている ◯。Square オンラインビジネスのプラスプランでネットショップからサブスクを受け付けられる旨の案内あり ◯ | 月会員の「受講回数」の管理と、Square予約での予約を自動で結び付けられるかは未確認 × |
| 回数券 | Square予約の「パッケージ」は米国版ヘルプで確認 △。**日本で使えるかは未確認 ×** | 前払いの回数券は、有効期限や発行額によって法律上の届出が必要になる場合があるため、導入前に専門家へ確認を推奨 |
| 年間講座 | 一括払いなら通常の商品・クラスとして販売可能 | 分割・途中解約の扱いを決める必要あり |
| オンラインレッスン（ライブ） | 予約・支払いはSquareで可能。参加URLの配布方法は別途決める | URLを予約確認メールに入れるか、前日に個別送付か |

| 会員ページ（マイページ） | 独自開発が必要 | 個人情報を扱うため、セキュリティ要件がすべてかかる |

**リーフレットに月会員・年間講座・オンラインの記載があっても、それだけで実装範囲は確定しません。** 第12章の質問でご判断ください。

## 10. セキュリティ

### 10-1. 最小構成での考え方

最小構成では、**サイト側はお客様の個人情報・カード情報・Squareの秘密の鍵を一切持ちません。** 支払い・注文・予約・顧客情報はすべてSquareの中にあります。そのため、多くの要件は「Squareの設定と、アカウントの守り方」で満たします。

| 要件 | 最小構成での対応 | 担当 |
|---|---|---|
| 1. 決済 | カード入力はSquareの画面のみ。支払済みの判断はSquareの管理画面の記録で行い、「完了画面が出た」ことでは判断しない | Square／運営者 |
| 2. 管理画面 | Square・サイトの更新画面・ドメイン・公開先のすべてで、**担当者ごとに個別アカウント＋2段階認証**。Squareのスタッフ権限で必要な範囲だけ許可（権限の細かさはプランにより異なる可能性があり要確認 ×）。アカウント共有はしない | 運営者 |
| 3. 個人情報 | サイト側では集めない。お問い合わせはLINE等かSquareに寄せる。購入者・参加者一覧は公開しない（Squareの管理画面の中だけ）。保存期間と削除方法は決定事項として第12章で確認 | 運営者 |
| 4. 秘密情報と通信 | サイトは常時HTTPS。最小構成ではSquareの秘密の鍵を使わない | 制作 |
| 5. 不正操作 | 金額はSquare側で決まり、サイトから書き換えられない。入力フォームはSquare側 | Square |
| 6. 運用と復旧 | サイトの文章・写真は更新画面のサービス側に保存＋定期的な書き出し。障害時の連絡先と手順を一枚にまとめる | 運営者／制作 |
| 7. 公開前確認 | 10-3のテストを実施 | 制作＋運営者 |

### 10-2. 自動表示などの独自連携を追加する場合の対策（次の段階）

- Squareの秘密の鍵はサーバー側の設定にだけ置き、ブラウザーに渡すコードや公開の保存場所に含めない。読み取り専用の権限に絞る。
- Squareからの通知を受け取る場合は、署名を検証し、通知ごとのIDを記録して同じ通知を二度処理しない。
- 支払い状態の判断は、ブラウザーから送られた値ではなく、**サーバーからSquareに問い合わせた結果（金額・注文・状態）**で行う。
- 入力値の検証、連続アクセスの制限、エラー記録に個人情報や鍵を書かない。
- 独自に保存するデータのバックアップと復元手順、依存部品の更新手順を用意。

### 10-3. 公開前テスト項目

| テスト | 内容 |
|---|---|
| 他人の情報が見えない | サイトのどのページにも注文・予約・顧客情報が出ないこと。Squareの確認メールのリンクから他人の予約に行けないこと |
| 金額を書き換えられない | サイトのリンクを加工しても、Square画面の金額が変わらないこと |
| 二重決済 | 支払いボタンを連打・戻る操作をしても二重に請求されないこと |
| 定員超過 | 残り1席に2台から同時に申し込み、1件だけ成立すること |
| 売り越し | 在庫1の商品を2台から同時に購入し、1件だけ成立すること |
| 決済失敗 | 使えないカードで予約・購入が成立せず、残席・在庫が減らないこと（テスト用カード） |
| キャンセル・返金 | 返金後に残席が戻る／在庫が条件どおり戻ること、返金額が正しいこと |
| 通知の遅れ | 確認メールが遅れても、Square管理画面の記録が正しいこと |
| スマホ操作 | iPhone・Androidで、予約・購入が最後まで迷わず進めること |

### 10-4. 今回実施したこと・テスト結果・残る制約

- **実施したこと**：デザイン見本（HTML）の作成のみ。見本には入力欄も送信機能もなく、外部への通信は書体の読み込みだけです。ボタンは見本内でページ内を移動するだけで、Squareには接続していません。
- **テスト結果**：決済・予約・在庫に関わる仕組みはまだ作っていないため、**10-3のテストは未実施**です。「安全です」と言える段階ではありません。
- **残る制約**：
  - 同時申し込み時のSquare内部の処理は公開資料で確認できておらず、実機テストで確かめる必要があります。
  - Square側の画面のデザインは、Squareが許す範囲でしか変えられません。
  - Squareのサービス障害時は、予約・購入ができなくなります（Square側の対応範囲）。
  - 料金・機能の情報は検索結果の要約に基づいており、公式ページでの再確認が必要です。

## 12. 設計を確定するための質問（優先度の高い順）

### 最優先（これがないと設計が決まらない）

1. **販売主体と代金の受取人は同じですか？** 例：物販は講師個人、レッスンは教室（法人）など分かれていないか。分かれる場合はSquareアカウントや特定商取引法の表記が分かれます。
2. **リーフレット4枚とロゴの元データを送っていただけますか？**（今回は届いていません）
3. **Squareのアカウントはすでにお持ちですか？** お持ちなら、ご契約中のプラン、教室での対面決済もしているかを教えてください。
4. **月会員・年間講座を、今回のネット申し込みに含めますか？** 含める場合、月謝は自動課金にするか、受講回数の上限はあるか。
5. **レッスンのキャンセル規定**（何日前まで全額返金か、当日・無断欠席の扱い）と、**商品の返品条件**。

### 高（ページ構成・Square設定に影響）

6. オンラインレッスンはライブ配信だけですか、録画の動画配信もしますか？ 参加URLはどう届けますか？
7. 個別レッスンは、日時をお客様が直接選ぶ形と、先に相談を受ける形のどちらにしますか？
8. 商品の点数・種類、発送方法（宅配便・メール便など）、送料（全国一律・地域別・○円以上無料など）、店頭受け取りの有無。
9. 支払い方法はカードのみでよいですか？（他の方法を希望する場合、Square側の対応を確認します）
10. 講師は何名ですか？ 管理画面を使う人は何名で、それぞれ何を担当しますか？

### 中（公開前までに決めたい）

11. サイトの写真・文章を更新するのはどなたですか？ パソコンとスマホ、どちらで更新したいですか？
